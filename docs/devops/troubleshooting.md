# 성능 병목 현상을 식별하는 방법은 무엇인가요?

**성능 병목 현상을 식별하는 일반적인 방법**

1. **성능 지표 모니터링:**
    - **CPU 사용률:** CPU가 100%에 가깝게 사용된다면 CPU가 병목 현상의 원인일 수 있습니다.
    - **메모리 사용량:** 메모리가 부족하면 시스템 성능이 저하될 수 있습니다.
    - **디스크 I/O:** 디스크 입출력이 과도하게 발생하면 디스크가 병목 현상의 원인이 될 수 있습니다.
    - **네트워크 대역폭:** 네트워크 대역폭이 부족하면 네트워크 통신이 느려져 성능이 저하될 수 있습니다.
    - **데이터베이스 쿼리 성능:** 데이터베이스 쿼리가 느리면 데이터베이스가 병목 현상의 원인일 수 있습니다.
2. **프로파일링:**
    - **코드 실행 시간 측정:** 코드의 특정 부분에서 시간이 많이 소비되는지 확인합니다.
    - **메모리 사용량 분석:** 메모리 누수나 비효율적인 메모리 사용이 있는지 확인합니다.
    - **CPU 프로파일링:** CPU가 어떤 작업에 가장 많은 시간을 소비하는지 확인합니다.
3. **로그 분석:**
    - **오류 로그:** 시스템 오류 로그를 분석하여 문제 발생 원인을 파악합니다.
    - **성능 로그:** 시스템 성능 로그를 분석하여 성능 저하 지점을 찾습니다.
4. **시스템 자원 사용량 분석:**
    - **top, htop:** 실시간으로 시스템 자원 사용량을 확인합니다.
    - **vmstat, iostat:** 가상 메모리 및 디스크 I/O 통계를 확인합니다.
    - **netstat:** 네트워크 연결 상태를 확인합니다.

# TCP Timeout이 발생했을 때 해결 방법은 무엇인가요?

네트워크 레이어 측면에서 볼 때, 올바른 포트가 맞는지, 올바른 도메인 네임인지 확인한다. 또한 DNS작동이 잘 되는지 확인해본다.

애플리케이션 측면에서 서버의 리소스( CPU, Memory)를 확인하고 해당 애플리케이션이 정상 작동하는지 확인한다.

- 네트워크 연결성 확인:
    - ping 테스트로 기본적인 연결 확인
    - traceroute를 통해 패킷 경로 추적 및 병목 지점 파악
    - 올바른 IP 주소, 포트, 도메인 네임 사용 여부 확인
    - DNS 작동 확인
- 방화벽 및 보안 설정:
    - 클라이언트와 서버 양쪽의 방화벽 설정 확인
    - 필요한 포트가 개방되어 있는지 확인
- 네트워크 성능:
    - 네트워크 대역폭 및 지연시간 측정
    - 네트워크 혼잡도 확인
- TCP 설정:
    - TCP 윈도우 크기 조정
    - TCP keepalive 설정 확인
    - TCP 재전송 타이머 조정
- 서버 측 확인:
    - 서버 리소스(CPU, 메모리, 디스크 I/O) 모니터링
    - 애플리케이션 로그 분석
    - 서버 프로세스 상태 확인



# WAS에서 DB를 읽는 속도가 느린 경우의 개선 방법

DB를 읽는 속도가 느린 경우, 여러가지를 생각할 수 있는데

DB의 쿼리가 최적화 되지 않았거나 DB인스턴스의 리소스가 부족하거나 DB connection의 수가 충분하지 못할 수도 있다.

DB 쿼리 최적화, DB 스케일아웃, DB 튜닝

WAS 에서 캐싱 사용 등으로 개선할 수 있다.



# RDB CPU 사용률을 낮은데 Connection이 많은 경우 조치 방법

쿼리 성능이 낮아 여러 Connection이 장시간 DB와 연결 상태를 유지하고 있을 수 있습니다. 이는 CPU 사용률은 낮으나 Connection 수가 증가하는 원인

CPU 사용률이 낮다는 것은 DB가 충분히 여유가 있다는 것을 의미할 수 있지만, 다른 자원(메모리, I/O, 네트워크 등)이 병목

애플리케이션에서 Connection Pool을 통해 DB 연결을 관리하는데, Connection Pool 크기가 과도하게 클 경우 불필요한 DB 연결이 유지
