# 협업과 업무 프로세스

## 작업을 시작할 때

목표, 완료 기준, 영향받는 사용자, 담당자와 마감의 근거를 먼저 적는다. 구현 방식이 정해지지 않았어도 확정된 사실과 미결정을 구분하면 협업할 수 있다.

## 진행과 의사결정

큰 작업은 결과를 확인할 수 있는 작은 단위로 나눈다. 변경 이유와 대안을 결정 기록으로 남긴다. 진행 공유는 작업 목록보다 완료된 결과, 남은 불확실성, 도움이 필요한 지점을 중심으로 쓴다.

장애나 지연을 공유할 때는 관찰한 사실, 영향, 현재 완화 조치, 다음 확인 시점을 구분한다. 추측을 원인으로 확정하지 않는다. 긴급 변경은 책임자와 되돌리는 조건을 함께 정한다.

## 마무리 예시

“검색 응답 지연을 줄이기 위해 인덱스를 추가했다. 대표 쿼리의 계획과 p95를 비교했고 쓰기 비용도 확인했다. 다음 배포에서 오류율과 디스크 증가를 관찰한다.”처럼 결과와 검증을 연결한다. 실제 회사의 규정이나 개인 평가를 일반 원칙으로 옮기지 않는다.
